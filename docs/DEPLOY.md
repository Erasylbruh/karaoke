# Бесплатный деплой: Vercel + Firebase + Supabase

| Часть | Сервис | Тариф |
|---|---|---|
| Сайт (Next.js) | Vercel | Hobby, бесплатно. Только для некоммерческого использования: реклама, донаты или платные функции требуют тарифа Pro |
| Вход и база | Firebase Authentication + Firestore | Spark, бесплатно |
| Аудио, обложки, шрифты | Supabase Storage | Free, 1 ГБ |

Карта ни для одного из них не нужна.

## 1. Firebase (вход и база)

1. [Firebase Console](https://console.firebase.google.com/) → проект `karaoke-craft`.
2. **Authentication → Sign-in method → Email/Password → Enable.**
3. **Firestore Database → Create database** (режим production, регион любой).
4. Опубликовать правила из репозитория:
   ```bash
   npx firebase-tools login
   npx firebase-tools deploy --only firestore:rules
   ```
   или вставить `firestore.rules` в Firebase Console → Firestore → Rules → Publish.
5. **Authentication → Settings → Authorized domains → Add domain**: добавить домен сайта, например `karaokecraft.vercel.app`. Без этого вход на опубликованном сайте не сработает.

Подробности о данных и правилах лежат в [FIREBASE.md](FIREBASE.md).

## 2. Supabase (файлы)

1. [supabase.com](https://supabase.com/) → New project (бесплатный тариф).
2. **SQL Editor** → выполнить [supabase/storage.sql](../supabase/storage.sql). Скрипт создаёт публичный бакет `uploads` (до 40 МБ на файл, только аудио, шрифты и картинки).
3. **Project Settings → API Keys**: скопировать `Project URL`, публичный ключ (`sb_publishable_…` или `anon`) и **секретный** ключ (`sb_secret_…` или `service_role`).
4. Для локальной разработки создать `.env.local` по образцу [.env.example](../.env.example).

Как устроена загрузка: браузер просит у `/api/storage/upload` одноразовую подписанную ссылку. Роут проверяет вход, подтверждённую почту и бан, затем браузер отправляет файл прямо в Supabase. Поэтому файлы не упираются в лимит тела запроса Vercel. Удаление файлов идёт через `/api/storage/delete`. Обоим роутам нужен секретный ключ `SUPABASE_SERVICE_ROLE_KEY`.

Если секретного ключа нет, сайт загружает файлы напрямую публичным ключом. Это работает только с политикой из [supabase/storage.dev.sql](../supabase/storage.dev.sql) и годится лишь для отдельного тестового проекта.

## 3. Vercel (сайт)

1. Залить проект на GitHub.
2. [vercel.com](https://vercel.com/) → Add New → Project → выбрать репозиторий. Framework определится как Next.js.
3. **Settings → Environment Variables** (Production и Preview):

   | Переменная | Что это |
   |---|---|
   | `NEXT_PUBLIC_SITE_URL` | Адрес сайта для ссылок и sitemap, например `https://karaokecraft.vercel.app` |
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL из Supabase |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ Supabase |
   | `NEXT_PUBLIC_SUPABASE_BUCKET` | `uploads` |
   | `SUPABASE_SERVICE_ROLE_KEY` | **Секретный** ключ Supabase. Без приставки `NEXT_PUBLIC_`, иначе он попадёт в браузер |
   | `NEXT_PUBLIC_CONTACT_EMAIL`, `NEXT_PUBLIC_OPERATOR_NAME` | Необязательно: контакт и владелец для документов сайта, по умолчанию из `lib/legal.ts` |
   | `NEXT_PUBLIC_ALIGNER_URL` | Необязательно: постоянный адрес сервиса авто-тайминга, когда он переедет на сервер (CSP подхватит его сам) |
   | `STORAGE_USER_QUOTA_MB` | Необязательно: сколько МБ файлов может хранить один аккаунт, по умолчанию 300. Админов лимит не касается |
   | `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` | Необязательно: ключ сайта reCAPTCHA v3 для App Check (см. FIREBASE.md, раздел «App Check») |

   Статистика посещений: Vercel → проект → **Analytics → Enable** и **Speed Insights → Enable**. Код уже подключён (`app/layout.tsx`); пока в Vercel статистика не включена, она просто не собирается.

4. Deploy. После каждого push в `main` сайт пересобирается сам, поэтому изменения сначала проверяйте в отдельной ветке (Vercel даёт для неё preview-адрес).

## Порядок выкатки обновления от 21.11.2026 (ветка `fix/public-launch`)

Порядок важен: правила и код выкатываются отдельно.

1. **Подтвердите почту своего админ-аккаунта** (ссылка из письма или «Отправить ещё раз» на сайте). Новые правила пускают публикацию треков и отзывов только с подтверждённой почтой.
2. **Опубликуйте `firestore.rules`.** Старый код сайта с новыми правилами в основном работает. Исключения: смена тега в старом коде не сохранится, а треки и отзывы с неподтверждённой почты пропадут без сообщения. Поэтому шаг 3 делайте сразу за этим.
3. **Слейте ветку в `main`** и дождитесь сборки Vercel. Новый код, наоборот, работает и со старыми правилами, кроме удаления аккаунта: оно честно откажет, ничего не удалив.
4. **Админка → Пользователи → «Зарезервировать теги»**: закрепляет теги профилей, созданных до резервирования.
5. **Добавьте `SUPABASE_SERVICE_ROLE_KEY` в Vercel** и пересоберите сайт (Deployments → Redeploy). Проверьте загрузку песни на 8–10 МБ: она должна пройти.
6. **Закройте анонимную загрузку**: в Supabase → SQL Editor выполните
   `drop policy if exists "uploads: anyone can upload" on storage.objects;`
7. Проверьте: загрузка обложки и песни работает; на сайте без входа нельзя загрузить файл; удаление трека в Creator Studio убирает и его файлы; удаление тестового аккаунта проходит до конца.

**Не объявляйте сайт публично, пока не выполнен шаг 6.** До него анонимная загрузка в бакет открыта, а политика конфиденциальности уже обещает, что загружать файлы могут только вошедшие пользователи с подтверждённой почтой. До шага 5 удаление аккаунта честно отказывает («на сервере не настроено удаление файлов»).

## Что важно перед публичным запуском

- **Документы и закон**: см. `docs/PUBLISH_AUDIT.md` (не коммитьте его в публичный репозиторий до закрытия пунктов). Там перечислены требования законов РК, что уже сделано в коде и что нужно решить с юристом.
- **Жалобы**: закон РК «Об онлайн-платформах и онлайн-рекламе» требует мотивированного ответа на жалобу не позднее 20 календарных дней. Жалобы с сайта видны в `/admin/reports`, там же можно ответить заявителю. На почту `karaokecraft1@gmail.com` поставьте автоответ, подтверждающий получение письма.
- **Лимиты бесплатных тарифов**: Supabase — 1 ГБ хранилища и около 2 ГБ трафика в месяц, этого хватит примерно на 200 треков по 5 МБ. Firebase Spark — 50 000 чтений и 20 000 записей в день. Сейчас сайт при каждом открытии загружает все коллекции целиком, поэтому чтения расходуются быстро. При росте нужно перейти на запросы по страницам.
