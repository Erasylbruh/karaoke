# Аудит и шаги к релизу

Аудит от 16.11.2026. Методика — `impeccable audit` (5 направлений, оценка 0–4) и чек-лист `ui-ux-pro-max`.

**Как проверялось**:
- проверщик `impeccable` по исходникам;
- обход гостевых страниц во встроенном браузере на ширине 1366 и 375 px: главная, плеер, профиль автора, вход, регистрация;
- измерения через REST Firestore.

Проверщик `impeccable` не смог запустить свой браузер, поэтому проверки по отрисованной странице (контраст, мелкий текст, цели касания, подписи, `alt`, заголовки, горизонтальная прокрутка) сделаны своим скриптом в браузере. Страницы за входом (редактор, студия, админка) не открывались.

## Блокеры релиза (P0)

**Состояние на 16.11.2026: пункты 1–4 исправлены в коде, ждут выкатки.** Что сделано:
- личные коллекции читаются только запросами «мои»;
- email и данные модерации перенесены в `userPrivate`;
- новые `firestore.rules` без даты окончания, с проверкой владельца;
- 11 групп тестов правил в эмуляторе проходят;
- сайт целиком проверен против эмулятора: регистрация, вход, лайк, подписка, отзыв, плейлист, уведомления, статистика, закрепление, перенос данных, предупреждение.

Порядок выкатки (важен, иначе часть функций сломается на несколько минут):
1. Запушить код и дождаться, пока Vercel пересоберёт сайт.
2. Сразу опубликовать `firestore.rules`: Firebase Console → Firestore → Rules или `npx firebase-tools deploy --only firestore:rules`.
3. Войти администратором → `/admin/users` → «Скрыть личные данные». Это переносит email и данные модерации старых профилей в закрытую часть.
4. Проверить: запрос `https://firestore.googleapis.com/v1/projects/karaoke-craft/databases/(default)/documents/users` больше не содержит `email`, а `.../notifications` отвечает 403.

Вход по тегу убран: теперь только по email, иначе email всех пользователей пришлось бы держать в открытом доступе.

Исходные находки:


1. **Личные данные читаются без входа.**
   - Через REST API кто угодно получает коллекцию `users` с email, `warnings` и `banReason` всех пользователей.
   - Так же открыты `notifications` (в том числе тексты предупреждений модерации) и `downloads` (история скачиваний).
   - Причина в `firestore.rules`: `allow read: if true` для `users` и `notifications`, открытое чтение старых коллекций.
2. **Тестовый режим базы кончается 31.12.2026.**
   - После этой даты перестанут работать записи в `comments`, `playlists`, `follows`, `likes`, `interactions`, `events`, `downloads`, `notifications` и гостевая статистика треков.
   - У всех сломаются лайки, отзывы, подписки, плейлисты, уведомления и счётчик прослушиваний.
   - До даты около 6 недель.
3. **Сейчас любой может менять и удалять чужие** отзывы, лайки, плейлисты и подписки: в правилах старых коллекций нет проверки владельца.
4. **Архитектура данных.**
   - `lib/store.ts` подписывает каждого посетителя на все коллекции целиком, включая всех пользователей и все уведомления.
   - Пока так, закрыть чтение правилами нельзя: подписка на всю коллекцию просто упадёт.
   - Нужны запросы по владельцу (`where('userId', '==', uid)`) для уведомлений, загрузок, лайков и плейлистов, публичный профиль без email и только потом строгие правила.
   - Это главный объём работы перед релизом.

## До релиза (P1)

5. **Загрузки в Supabase открыты всем, у кого есть публичный ключ**, а это любой посетитель сайта. Он может заполнить бесплатный 1 ГБ мусором. Загрузку нужно вести через API-роут Vercel с проверкой Firebase-токена (см. `docs/DEPLOY.md`).
6. **Обложки внутри документов треков.** Выполнить SQL из конца `supabase/storage.sql` и нажать «Перенести обложки» в `/admin/tracks`. Это заметно уменьшит объём, который скачивает каждый посетитель.
7. **Лимиты бесплатного Firestore.**
   - 50 000 чтений в день.
   - При текущей подписке на всё каждый визит читает все документы всех коллекций. С ростом каталога лимит кончится уже при сотнях посетителей в день.
   - Решается тем же пунктом 4.
8. **Заголовки и превью ссылок.**
   - У всех страниц одинаковый `<title>` «KaraokeCraft — караоке-анимации», `metadata` есть только в `app/layout.tsx` и `app/create`.
   - Ссылка на трек в мессенджере выглядит так же, как ссылка на главную.
   - Нужны `generateMetadata` для `/karaoke/[id]`, `/u/[tag]`, `/artist/...`, `/tag/...` с названием, обложкой и Open Graph.
9. **Контраст таймера плеера.** `0:00 / 2:14` на полупрозрачной подложке (`#player .player-times`) даёт около 3,4:1 на светлых треках (Bella Ciao), норма WCAG AA — 4,5:1. Нужна плотнее подложка или белый текст без прозрачности.
10. **Уязвимости зависимостей.** `npm audit` показывает 4 high в `@grpc/grpc-js` внутри `firebase`. Это серверная часть gRPC, в браузере риск низкий, но `firebase` стоит обновить.
11. **Проверка на настоящих телефонах**: Safari на iPhone (WebCodecs, фолбэк записи видео, HEIC) и Chrome на Android. Сейчас проверено только в эмуляции.
12. **Сервис автотайминга** (`aligner/`) работает на локальной машине через туннель. Для релиза нужно решить, где он живёт, или честно отключить функцию, когда сервис недоступен.

## Сразу после релиза (P2)

13. **Подсказка на телефоне.** Подсказка каталога говорит «Наведите курсор», а на телефоне курсора нет. Карточка подсказки на телефоне закрывает панель плеера, пока её не закрыть.
14. **Подвал.** Строка «Next.js • Tailwind CSS • Web Audio API» шрифтом 11 px и блок «Водяной знак» написаны для разработчика, а не для слушателя. Их стоит заменить ссылками: о проекте, правила, связь.
15. **Порядок заголовков.** Подсказка рендерит `h4` раньше `h1`, в подвале `h4` идут сразу после `h2`.
16. **Прослушивание в фоновой вкладке не засчитывается**: часы плеера идут через `requestAnimationFrame`.
17. **Цвета мимо токенов.** Плеер, панель загрузок и диалоги используют `#18181b`, `#27272a`, `#f4f4f5`, `#a1a1aa` напрямую вместо `--s1`, `--s2`, `--tx`, `--mu`.
18. **Мелкие цели касания.** Логотип 159×22 и ссылка автора в плеере 66×20 ниже 24 px по высоте.
19. **Lint.** 20 старых ошибок `react-hooks/set-state-in-effect`: сборка проходит, но для CI их стоит убрать.

## Организационное

- **Документы.** Политика конфиденциальности и пользовательское соглашение: сайт хранит email и даёт загружать чужую музыку. Порядок жалоб на авторские права уже есть («Пожаловаться на проект»).
- **Хостинг и вход.** Свой домен в Vercel, добавить его в Firebase → Authentication → Authorized domains, переменные `NEXT_PUBLIC_SUPABASE_*` в Vercel.
- **Мониторинг ошибок** (например, Sentry) и простая аналитика посещений.
- **Резервная копия Firestore.** На бесплатном тарифе автоматических бэкапов нет, нужен ручной экспорт перед закрытием правил.
