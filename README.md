# KaraokeCraft

Веб-платформа для создания, настройки и воспроизведения караоке-анимаций в стиле Spotify Lyrics: строки текста синхронизируются с музыкой, трек публикуется в каталоге, а готовую анимацию можно скачать видео с водяным знаком.

## Роли на сайте

Роль хранится в поле `User.role` (`'user' | 'admin'`) в [lib/types.ts](lib/types.ts). Проверки выполняются только на клиенте (`useAuth().isAdmin`), поэтому это модель прав интерфейса, а не защита.

| Роль | Кто это | Что может |
| --- | --- | --- |
| **Гость** | не вошёл (`status: 'guest'`) | смотреть каталог, искать и сортировать, слушать треки, читать комментарии, открывать студию, создавать трек, скачивать видео он не может. Видит кнопки «Войти» / «Регистрация» |
| **Пользователь** (`user`) | зарегистрирован | всё, что гость, плюс: лайки, комментарии, удаление **своих** комментариев, личный профиль (имя, био, аватар), список своих публикаций и лайков, открывать студию, создавать трек, скачивать видео |
| **Администратор** (`admin`) | модератор | всё, что пользователь, плюс: страница `/admin` («Модерация»), удаление **любых** комментариев, закрепление треков как «рекомендованных», удаление треков, назначение/снятие роли admin, удаление пользователей (кроме себя), просмотр сводной статистики |

## Задачи (возможности)

**Для слушателя**
- Каталог с поиском (по названию, исполнителю, автору и тегам; «ё» = «е»), фильтром по тегам и сортировкой: Рекомендуем, Популярные, Новые, Старые. Состояние хранится в URL (`?q=`, `?tag=`, `?sort=`).
- Плеер в стиле Spotify Lyrics: плавная прокрутка, перемотка по клику на строку, горячие клавиши (Пробел, ←/→), счётчик прослушиваний.
- Лайки и комментарии под треком.

**Для автора (студия `/create`)**
- Ввод текста в формате **LRC** или запись таймингов **«На слух»**: вставить текст и тапать по строкам под музыку.
- Оформление: шрифт (12 вариантов), цвет активной и неактивной строки, фон (mesh, obsidian, gradient, aura, particles, свой), размер шрифта, обложка/иконка, формат 9:16 или 16:9.
- Метаданные: название, исполнитель, описание, теги; выбор музыкального пресета (synthwave, lofi, pop, cyberpunk, chill, rock).
- Живой предпросмотр и публикация в каталог.
- Экспорт видео из Canvas через MediaRecorder (30 FPS) с защитным водяным знаком «✦ KaraokeCraft • Spotify Lyrics Animation».

**Для аккаунта**
- Регистрация и вход (`/register`, `/login`), редирект на нужную страницу после входа.
- Профиль: редактирование имени, био, аватара; свои публикации и понравившиеся треки.

**Для администратора**
- Дашборд: число треков, пользователей, лайков, прослушиваний.
- Вкладки «Треки», «Пользователи», «Система» (описание водяного знака и окружения).
- Все разрушительные действия подтверждаются модальным окном.

## Архитектура

Клиентское приложение на Next.js App Router. Серверной логики нет; страницы рендерятся как клиентские компоненты поверх «базы» в `localStorage`.

```
┌────────────────────────────── Браузер ──────────────────────────────┐
│                                                                     │
│  app/ (страницы, App Router)                                        │
│    /  /karaoke/[id]  /create  /profile  /admin  /login  /register   │
│        │                                                            │
│  components/ ── ui (кнопки, модалки, поля) · layout · catalog       │
│        │         player · studio · karaoke · admin · auth · profile │
│        │                                                            │
│  context/AuthContext ── действия: login / register / logout /       │
│        │                switchUser / updateProfile                  │
│        ▼                                                            │
│  lib/store.ts ── useSyncExternalStore-хуки (чтение, реактивность)   │
│        ▼                                                            │
│  lib/storage.ts ── CRUD + подписки (запись, notify)                 │
│        ▼                                                            │
│  localStorage  ◄── seed из lib/mock-data.ts при пустом хранилище    │
│                                                                     │
│  lib/audio-synthesizer.ts (Web Audio) ──► плеер и экспорт видео     │
│  lib/lrc · tap-sync · lyrics · catalog · format · login (чистая     │
│                                                  логика + тесты)    │
└─────────────────────────────────────────────────────────────────────┘
```

**Слои и ответственность**

| Слой | Файлы | Назначение |
| --- | --- | --- |
| Маршруты | `app/**/page.tsx`, `app/layout.tsx` | страницы, метаданные, общий каркас (шапка, подвал, провайдеры) |
| UI-кит | `components/ui/*` | единая дизайн-система «Сцена»: `button`, `chip`, `field`, `modal`, `menu`, `segmented`, `toast`, `skeleton`, `avatar` |
| Фичи | `components/{catalog,player,studio,karaoke,admin,auth,profile,layout}` | компоненты по доменам |
| Состояние | `context/AuthContext.tsx`, `lib/store.ts` | текущий пользователь и подписки на данные |
| Данные | `lib/storage.ts`, `lib/mock-data.ts`, `lib/types.ts` | «репозиторий» поверх localStorage, seed, типы |
| Домен | `lib/lrc.ts`, `tap-sync.ts`, `lyrics.ts`, `catalog.ts`, `login.ts`, `format.ts` | чистые функции, покрыты тестами |
| Медиа | `lib/audio-synthesizer.ts`, `components/karaoke/VideoDownloaderModal.tsx` | процедурная музыка и запись видео |

**Ключевые решения**

1. **Хранилище как внешний store.** `storage.ts` пишет в `localStorage` и вызывает `notify()`; `store.ts` читает через `useSyncExternalStore` с кешем по сырой строке. Изменения в одной вкладке сразу видны всем компонентам, а в других вкладках — через событие `storage`.
2. **Безопасная гидратация.** Серверный снимок хуков — `null`/`undefined`, поэтому пользователь, данные и скелетоны появляются только после монтирования; нет рассинхрона SSR/клиента и мигания «Войти».
3. **`useAuth` читает пользователя сам.** Провайдер отдаёт только неизменяемые действия, а текущего пользователя каждый потребитель берёт из store — иначе значение просочилось бы в ещё не гидратированные Suspense-границы (шапка).
4. **Seed при первом запуске.** Пустые ключи заполняются данными из `mock-data.ts`.
5. **Синтезатор вместо аудиофайлов.** Музыка генерируется Web Audio API и выводится в `MediaStreamDestination`, поэтому звук попадает и в записанное видео.
6. **Чистая логика отдельно от React.** Разбор LRC, тап-синхронизация, поиск/сортировка каталога и правила входа — функции без побочных эффектов с тестами `*.test.ts`.
7. **Дизайн-токены.** Цвета, радиусы и шрифты заданы в `@theme` в `app/globals.css`; сложные эффекты — именованные классы там же. Подробности — в [docs/superpowers/specs](docs/superpowers/specs/2026-10-28-karaokecraft-redesign-design.md).

**Модель данных** (`lib/types.ts`)

- `User` — id, username, name, email, avatar, bio, `role`, createdAt
- `Karaoke` — метаданные, `lyrics: LyricLine[]`, `style: KaraokeStyle`, `audioPreset`, автор, `likesCount`, `viewsCount`, `isFeatured`, `recommendationScore`
- `Comment` — karaokeId, userId, content
- Ключи localStorage: `karaokecraft_karaokes`, `_comments`, `_users`, `_current_user`, `_liked_posts`

**Маршруты**

| Путь | Назначение |
| --- | --- |
| `/` | каталог и витрина |
| `/karaoke/[id]` | плеер, комментарии, скачивание видео |
| `/create` | студия создания трека |
| `/profile` | профиль и свои треки/лайки |
| `/admin` | модерация (только админ) |
| `/login`, `/register` | вход и регистрация |

## Ограничения и план развития

Текущие ограничения:
- данные живут только в браузере: нет общей базы, у каждого посетителя свой каталог;
- пароль не проверяется, права проверяются лишь на клиенте;
- нельзя загрузить свой аудиофайл — только встроенные пресеты;
- экспорт видео зависит от поддержки MediaRecorder в браузере;
- только русский язык и тёмная тема.

Что логично сделать дальше:
- бэкенд и база данных (например, Postgres + Prisma) вместо `localStorage`;
- настоящая аутентификация (хеши паролей, сессии/JWT) и серверная проверка ролей;
- загрузка аудио в объектное хранилище, серверный рендер видео;
- пагинация каталога и серверный поиск;
- светлая тема и i18n.
