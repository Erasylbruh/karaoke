# Aligner: автоматическая расстановка таймингов

Небольшой сервис на Rust, который работает на вашем компьютере. Редактор сайта отправляет ему аудио и текст песни, а получает начало и конец каждой строки (и каждого слова).

Как работает:
1. Аудио (mp3, m4a/aac, ogg, wav, flac) декодируется и переводится в 16 кГц моно.
2. [whisper.cpp](https://github.com/ggerganov/whisper.cpp) распознаёт слова, а DTW по «головам выравнивания» модели даёт точное начало каждого слова.
3. Распознанные слова сопоставляются с текстом автора (Needleman–Wunsch с нечётким сравнением слов). Поэтому тайминги ложатся на настоящий текст, даже если Whisper ослышался. Если слово не распознано, его время подставляется между соседними.

На тестовой записи начало строки отличается от настоящего в среднем на 0.07 с. Обработка занимает около 6 с на 30 с аудио на i5-12400F; песня на 3 минуты займёт примерно 35–40 с.

## Запуск

```powershell
cd aligner
.\start.ps1
```

Скрипт сам соберёт программу (если нужно) и скачает модель `ggml-small.bin` (~470 МБ). Пока окно открыто, кнопка «Авто-тайминг» в редакторе работает и на `localhost`, и на сайте в Vercel: браузер обращается к `http://localhost:8787` на вашем же компьютере.

## Сборка с нуля

Нужны:
- Rust: `winget install Rustlang.Rustup`;
- Visual Studio Build Tools с компонентом C++ (в них есть CMake);
- LLVM (нужен libclang): `winget install LLVM.LLVM`.

```powershell
.\build.ps1
cargo test --release   # проверки сопоставления и декодирования
```

`build.ps1` включает AVX2 и `/O2`: без них MSVC собирает whisper.cpp примерно в 8 раз медленнее.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `WHISPER_MODEL` | `models/ggml-small.bin` | Модель. `ggml-medium.bin` точнее, но в 2–3 раза медленнее |
| `ALIGNER_HOST` | `127.0.0.1` | Адрес, который слушает сервис. На сервере или в контейнере — `0.0.0.0`; тогда каждый запрос требует вход в аккаунт сайта |
| `ALIGNER_PORT` | `8787` | Порт |
| `ALIGNER_REQUIRE_AUTH` | — | `1` — требовать Firebase ID-токен у каждого запроса. Включается само, если `ALIGNER_HOST` не локальный; иначе токен нужен только запросам через туннель |
| `ALIGNER_ORIGINS` | — | Дополнительные адреса сайта через запятую. Всегда разрешены karaokecraft.vercel.app и localhost на любом порту |
| `ALIGNER_DEBUG` | — | Печатать каждое распознанное слово и время работы |
| `ALIGNER_EMAIL`, `ALIGNER_PASSWORD` | — | Учётная запись сервиса для публикации адреса туннеля (см. «Учётная запись сервиса»). Удобно хранить в `aligner\.env` |
| `ALIGNER_PUBLIC` | `1` | `0` — не запускать туннель, только этот компьютер |

## Доступ с телефона и других компьютеров

`start.ps1` вместе с сервисом запускает бесплатный туннель Cloudflare (`cloudflared`, аккаунт не нужен). Туннель даёт вашему ПК публичный адрес вида `https://….trycloudflare.com`.

> Cloudflare пишет, что Quick Tunnels предназначены для тестов и разработки, а для постоянной работы нужен обычный Cloudflare Tunnel. У них нет гарантии доступности и не больше 200 одновременных запросов. Для публичного сайта сервис лучше перенести на сервер с постоянным адресом. Задайте его в `NEXT_PUBLIC_ALIGNER_URL` (Vercel → Environment Variables): сайт будет ходить туда, а CSP (`next.config.ts`) разрешит этот адрес сам. Пока сервис работает на вашем ПК, учтите: отправлять ему файлы может любой вошедший пользователь, а аудио обрабатывается в памяти и не сохраняется (это описано в политике конфиденциальности).

1. Aligner записывает этот адрес в Firestore (`config/aligner`) и обновляет его раз в минуту.
2. Сайт на любом устройстве читает адрес оттуда и отправляет авто-тайминг на ваш ПК.
3. При остановке (Ctrl+C) адрес стирается, и сайт перестаёт ждать этот сервер.

Ограничения:
- Работает, только пока ПК включён и окно `start.ps1` открыто. Песни обрабатываются по одной.
- Адрес меняется при каждом запуске, но сайт находит его сам.
- Адрес публичный, поэтому запросы через туннель принимаются только с действительным Firebase ID-токеном вошедшего пользователя, плюс действуют CORS, лимит 60 МБ и 15 минут на файл (с ранней проверкой при декодировании), ограничение очереди и одна задача за раз.

Нужен cloudflared: `winget install Cloudflare.cloudflared`. Без него сервис работает только на этом компьютере. Отключить туннель можно переменной `ALIGNER_PUBLIC=0`.

### Учётная запись сервиса

Правила Firestore разрешают писать в `config/aligner` только отдельной учётной записи Firebase, и только адрес `https://….trycloudflare.com` (или пустую строку) и время. Без неё aligner пишет в лог `ALIGNER_EMAIL / ALIGNER_PASSWORD are not set` и работает только на этом компьютере (туннель не запускается). Настраивается один раз:

1. Firebase Console → Authentication → Users → **Add user**. Укажите отдельный email и длинный пароль (не ваш личный). Скопируйте **User UID** новой записи.
2. Firebase Console → Firestore → коллекция `services`, документ `aligner`, поле `uid` (строка) = скопированный UID. С сайта этот документ не прочитать и не изменить: его меняют только в консоли.
3. Скопируйте `aligner\.env.example` в `aligner\.env` и впишите `ALIGNER_EMAIL` и `ALIGNER_PASSWORD`. Файл `.env` не попадает в git; `start.ps1` загружает его сам. Можно задать те же переменные и в системе.
4. Запустите `.\start.ps1`. В логе появится `public address: https://….trycloudflare.com`, а в Firestore у документа `config/aligner` обновится `updatedAt`.

В `services/aligner` помещается один UID, поэтому второй разработчик, запуская aligner у себя, использует ту же учётную запись (передайте email и пароль лично, не через репозиторий).

Если в логе `Firebase sign-in refused`, проверьте email и пароль. Если `Firestore refused the write (403)`, значит UID в `services/aligner` не совпадает с учётной записью или на проекте ещё старые правила (`firebase deploy --only firestore:rules`).

## На сервере (Docker, не проверено)

`Dockerfile` и `docker-entrypoint.sh` написаны без запуска Docker: соберите образ и проверьте один запрос, прежде чем на них полагаться.

```bash
docker build -t karaokecraft-aligner aligner
docker run -d --restart unless-stopped -p 127.0.0.1:8787:8787 -v aligner-models:/models karaokecraft-aligner
```

- При первом запуске контейнер скачивает модель `ggml-small.bin` (~470 МБ) в том `/models` и проверяет её SHA-256.
- Внутри контейнера сервис слушает `0.0.0.0`, поэтому каждый запрос требует Firebase ID-токен вошедшего пользователя. Туннель выключен (`ALIGNER_PUBLIC=0`), `config/aligner` не нужен.
- Сайт работает по HTTPS, поэтому и сервису нужен HTTPS-адрес: поставьте перед контейнером обратный прокси с сертификатом (например, Caddy или Nginx + Let's Encrypt), который пересылает запросы на `127.0.0.1:8787`.
- Адрес укажите в Vercel → Environment Variables → `NEXT_PUBLIC_ALIGNER_URL` (например, `https://align.example.com`) и пересоберите сайт. CSP разрешит этот адрес сам (`next.config.ts`).
- Если сайт открыт не только на `karaokecraft.vercel.app`, добавьте его адрес в `ALIGNER_ORIGINS` (`docker run -e ALIGNER_ORIGINS=https://ваш-домен ...`).
- Модели нужно около 1–2 ГБ памяти; песня на 3 минуты обрабатывается от десятков секунд до нескольких минут в зависимости от процессора.

## API

`POST /align` (multipart):
- `audio` — файл;
- `lyrics` — JSON-массив строк;
- `language` — `ru`, `en`, `kk` или `auto`.

Ответ:

```json
{ "language": "ru", "duration": 179.2, "elapsed_ms": 38000, "confidence": 0.92,
  "lines": [ { "index": 0, "start": 3.08, "end": 5.0, "confidence": 1.0,
               "words": [ { "text": "Я", "start": 3.08, "end": 3.3, "matched": true } ] } ] }
```

`confidence` строки — доля её слов, которые реально распознаны. Если она меньше 0.5, строку стоит проверить вручную; редактор помечает такие строки знаком «?».

`GET /health` возвращает `{ "ok": true, "model": "ggml-small.bin", "busy": false }`.
